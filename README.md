# 牛速（fnOS Speedtest）

面向飞牛 fnOS 的轻量级公网测速桌面应用。测速流量直接从 NAS 发出，使用 Speedtest.cn、Speedtest.net 及经验证的公开 HTTP 节点测量 NAS 的公网下载、上传、空闲延迟与抖动。

## 功能

- 快速、标准、深度三档测速模式
- 根据 NAS 公网出口 IP 自动识别运营商、省份，支持 IPv4/IPv6
- 界面显示中文运营商、省份；同省节点及同省同运营商节点带标记
- 增加省份和城市定向搜索，延迟接近时优先同省节点
- 综合候选节点实测延迟、抖动、距离和同运营商匹配自动选出最佳节点
- 显示公网 IP、网络运营商、节点名称、节点运营方和节点 ID
- 多连接下载与上传测速
- 测速过程中实时显示下载、上传速度和延迟
- 下载、上传独立进度条
- 自动推荐最佳节点，也可从 Speedtest.cn、Speedtest.net、运营商、高校分组中手动选择
- 开始测速后直接连接已选择节点，不再重复优选
- 取消测速后立即停止界面进度和实时数值更新
- 开始／取消测速合并为一个按钮，停止期间禁用
- 删除测速卡片下方日志框，错误仅在操作区显示
- 从 Speedtest 当前目录补充中国境内电信、联通、移动节点，按 ID 去重
- 对候选节点进行预热及 3 次 HTTP 延迟检测，过滤无效响应与连接失败节点
- 中国境内节点在下拉列表中分组，显示延迟和抖动
- 高对比度白色界面
- 网络信息区显示公网 IP、节点、省份和运营商，移除耗时
- 最近 50 条本地历史记录
- 使用 fnOS 统一网关，无需暴露额外局域网端口
- 单个静态链接 x86-64 可执行文件，无 Python/Node/Docker 依赖
- 禁止页面到达顶部或底部后的过度滚动与回弹

## 安装

1. 在飞牛桌面打开“应用中心”。
2. 进入“设置”并选择“手动安装应用”。
3. 上传 `fnos-speedtest-1.10.4-x86_64.fpk`。
4. 安装完成后，从桌面点击“牛速”。

最低系统版本为 fnOS `1.1.3100`，硬件架构为 Intel/AMD x86-64。

## 测速模式

- 快速：单连接省流量模式，适合快速检查。
- 标准：最多 4 个并发连接，适合常规宽带。
- 深度：最多 8 个并发连接，适合千兆及更高速率网络。

Speedtest.net 会根据线路速度自适应测速数据量，因此每次消耗流量可能不同。历史记录保存在应用数据目录。

## 节点筛选说明

节点来自当前 Speedtest.net 目录，不写死节点地址。并行请求附近节点、中国及三大运营商目录，去重后最多探测 60 个候选；保留附近节点，并为国内各运营商预留候选名额。任一补充目录失败时，继续使用其他可用目录。推荐分数主要取决于 HTTP 延迟与抖动，延迟接近时优先同运营商。列表中的“中国境内”分组按目录 CN 标记（或 China 国别）识别。

三次探测只能反映当前连通性及短时延迟稳定性，不能保证长期稳定或跑满带宽；实际吞吐量以 NAS 上的下载／上传测速为准。点击开始只使用已选节点 ID，不再次优选。

## 公网 IP 归属地识别

公网 IP 优先来自 NAS 后端连接 Speedtest.net 获得的信息，失败时使用 ipwho.is 的 NAS 出口查询，不使用访问网页的手机／电脑地址、浏览器定位或代理请求头。后端通过 HTTPS 将该公网 IP 传给 ipwho.is 查询省份和运营商，服务文档： https://ipwhois.io/documentation 。无需填写 API 密钥。

识别结果按 IP 缓存 30 分钟；IP 变化自动重新查询，失败短暂缓存 1 分钟。查询超时上限 4 秒，接口不可达、限流、返回其他 IP 或无有效省份时，界面显示“省份未识别”，继续使用 Speedtest 运营商信息和延迟选点。当前接口不是保证可用的专用服务。

省份依据 IP 数据库返回结果进行中文规范化，运营商识别包括电信／联通／移动／广电／教育网。节点省份依据其城市或省份名称保守匹配；无法确定的城市不标记“同省”。同省对推荐分数给予 10% 优先，同运营商给予 18% 优先，明显更快的外省节点仍可能成为推荐。开始测速仍直接使用选定 ID。

IP 归属地可能与物理所在地不同；多出口、代理或 VPN 情况下识别的是对测速服务可见的出口。历史结果保存本次检测的归属地信息。旧记录缺少归属地时不会套用其他 IP 的省份。

## 公开 HTTP 运营商／高校接入

v1.8.0 新增独立 HTTP 测速引擎，兼容公开 LibreSpeed 风格配置（`url_dl`、`url_ul`、`url_ping`）。刷新节点时先读取网站公开配置，限制同源接口，再完成预热、3 次延迟探测、小量二进制下载与 4 KiB 上传确认。仅通过全部检查的节点进入下拉列表；点击开始直接使用已经验证的选中地址，配置缓存 30 分钟。

内置候选前端如下。这里列的是探测候选，不代表已在当前构建环境验证其可用带宽接口：

| 候选站点 | 入口 | 探测条件 |
| --- | --- | --- |
| 广东电信 | https://10000.gd.cn/html5-speedtest/ | 公网 IP 识别为广东电信 |
| 南京航空航天大学虚拟仿真实验平台 | https://virtualsim.nuaa.edu.cn/speed/ | NAS 能直接访问公开兼容配置和接口 |
| 上海交通大学 | https://wsus.sjtu.edu.cn/speedtest/ | NAS 能直接访问公开兼容配置和接口 |

以上入口在本次构建环境均未完成远端连通验证，不能承诺安装后必定出现。自定义协议、跨站配置、页面改版、登录、浏览器验证、校园网限制、重定向或接口失败均会导致节点被跳过；不会把未验证候选伪装成可用节点。中科大、南京大学等需要浏览器验证的入口不纳入候选，也没有绕过验证的实现。当前没有接入各省电信／联通／移动私有测速协议。

列表优先考虑实测延迟、抖动及 IP 归属地／运营商匹配；同省并不保证同路由或跑满带宽。某个 HTTP 源失败不影响其他源，Speedtest 元数据服务失败时可通过 ipwho.is 的出口查询继续探测独立 HTTP 源。

HTTP 快速／标准／深度模式每个阶段最多 5／10／12 秒，最多 1／4／4 连接；下载流量预算 32／256／512 MiB，上传 16／128／256 MiB（另有少量验证流量）。先达到时间或预算即结束。速率以实际下载字节、完整发送且获成功响应的上传字节除以耗时计算，250 ms 更新一次采样；阶段超时的未确认上传不计入，因此慢速线路可能低估上传速率。与 Speedtest.net 的采样算法不同，数值可能有差异。

拒绝 HTML 下载、压缩响应、已有缓存及非空上传确认；取消会中断网络请求并等待工作线程退出，不写入取消结果。完整公网带宽测试仍需要在实际 NAS 线路验证。


## Speedtest.cn 中国节点（v1.10.0）

运行时读取 `spiritLHLS/speedtest.cn-CN-ID` 每日更新的中国大陆 Speedtest.cn 节点目录，不把节点地址写死在安装包中。程序按公网 IP 识别的省份和运营商排列候选，优先验证同省同运营商，再依次验证同运营商其他省、本省其他网络和其他中国节点；最多选择 24 个候选、并发验证 6 个。

节点发现阶段不再把延时探测当作硬门槛：先按 `ecsspeed` 的思路尝试 `pingUrl` HTTP 延时，失败后尝试 TCP 握手延时；两者都失败时节点仍保留为“延时待实测”。开始测速后才通过实际下载和上传接口判断节点是否真的可用。

节点列表按以下顺序分组，单行固定显示“地区｜运营商｜延迟｜抖动｜距离”，推荐节点单独置顶：

1. Speedtest.cn · 同省同运营商
2. Speedtest.cn · 同运营商其他省
3. Speedtest.cn · 本省其他网络
4. Speedtest.cn · 其他中国节点
5. 公开运营商节点／高校节点
6. Speedtest.net · 中国境内／其他附近

浙江大学（名称含“浙江大学”或域名含 `zju.edu.cn`）在目录解析阶段被明确过滤，不会出现在节点列表。根据此前的界面要求，v1.10.0 不再加载或显示全球网测节点。Speedtest.cn 目录不可达时会显示简短原因；单纯的延时预探测失败不会再清空 Speedtest.cn 节点。不会恢复测速卡片下方的日志框。

## v1.10.1 Speedtest.cn 连通性修复

- 请求方式与 `ecsspeed-cn` 当前实现保持兼容：Speedtest.cn 专用接口使用浏览器 User-Agent，不再添加额外查询参数，上传探测使用兼容的表单内容类型。
- 允许同一主机内最多 5 次 HTTP/HTTPS 重定向；跨主机重定向仍拒绝，避免目录节点把测速请求转交到未声明目标。
- 单节点验证时间由 6 秒增加到 12 秒，降低国内跨网线路首次建连较慢时被误判的概率。
- 全部候选失败时，在“没有通过连通性验证的节点”后显示数量最多的失败阶段和原因，例如延迟超时、HTTP 拒绝、下载或上传验证失败。

## v1.10.4 Speedtest.cn 预检查改为建议性

- 对照 `spiritLHLS/ecsspeed` 当前实现，节点发现阶段改为 HTTP 延时优先、TCP 握手延时兜底。
- HTTP/TCP 预检查都失败时仍保留节点，不再出现“没有通过连通性验证的节点；延迟探测失败 ×N”而把全部节点清空。
- 预检查失败节点在下拉框显示“延时待实测”，排序时放在已有有效延时的节点之后。
- 真正开始测速时，即使 `pingUrl` 失败，也会继续尝试下载/上传接口；下载/上传才是节点是否可用的最终判定。
- Speedtest.cn HTTP 请求允许正常的 HTTP/HTTPS 重定向，与 `curl -L` 的行为更接近。
- 仓库新增 `.github/workflows/build-fnos-fpk.yml`，在 GitHub Actions 使用 Go 1.22、官方 `speedtest-go` 依赖和官方 `fnpack 1.2.3` 构建 x86_64 FPK。

## 从源码构建

需要 Go 1.22+、ImageMagick 和飞牛官方 `fnpack` 1.2.3+：

```bash
chmod +x build.sh
./build.sh
```

开发模式：

```bash
go run . --listen 127.0.0.1:32892 --data-dir ./dev-data
```

然后打开 `http://127.0.0.1:32892/`。

## 验证

```bash
go test -race ./...
node web_ui_test.cjs
```

前端测试使用轻量 DOM 模拟，覆盖多源分组、单按钮状态、取消时的过期响应、手动选点、耗时移除及空历史。Go 本地 HTTP 服务测试覆盖协议解析、网站验证拒绝、下载／上传计数和预算、取消、无效响应、源失败隔离及缓存节点直连；这些测试不代表远端站点实测成功。完整公网探测可运行 `SPEEDTEST_INTEGRATION=1 go test -run TestLiveSpeedtestDiscovery -v`；完整带宽测速及飞牛安装仍需在实际 NAS 上验证。
